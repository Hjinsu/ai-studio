## 신규 및 잔존 결함

### RVX-01 · HIGH · 재로그인 이후 이전 지출 변경 요청이 자동 재전송됨

근거 ADR-037·061·066, [http.ts:73](../../frontend/src/api/http.ts#L73), [queryClient.ts:29](../../frontend/src/queryClient.ts#L29), [LoginPage.tsx:22](../../frontend/src/pages/LoginPage.tsx#L22).

Edge Mock API에서 첫 지출 변경 POST 응답을 보류했다. 동일 SPA에서 별도 보호 요청의 401로 세션을 만료시킨 뒤 다시 로그인했다. 새 세션의 화면이 이미 표시된 상태에서 이전 POST의 403을 반환하면 CSRF 재취득 분기가 같은 본문으로 POST를 다시 보냈다. 요청은 1건에서 2건으로 늘었고, 헤더가 이전 `tok-0`에서 새 `tok-1`로 바뀌었으며 대역의 지출 허용 플래그가 true가 됐다. 실제 지출·백엔드 변경은 수행하지 않았다.

403 재전송 분기 자체는 비교 기준선에도 있다. 이번 수정은 저장소의 mutation 캐시를 비워도 실행 중인 HTTP 작업에 세션 경계를 적용하지 않으므로 **재로그인 뒤 자동 재실행 금지**가 충족되지 않는다. 세션 식별 세대를 요청 시작에 고정하고 토큰 취득·응답·403 재전송 직전의 세대 검사를 추가한다. 같은 세션의 유효한 CSRF 복구 동작을 유지한다. 이전 세션의 늦은 403 이후 재전송 0건과 상태 불변을 회귀 검증한다.

### RVX-02 · MEDIUM · 이전 세션의 지연 401이 새 세션을 다시 만료 처리

근거 ADR-060·066, [queryClient.ts:19](../../frontend/src/queryClient.ts#L19), [queryClient.ts:50](../../frontend/src/queryClient.ts#L50).

RVX-01과 같은 순서에서 보류된 변경 응답을 401로 바꿨다. 재로그인 뒤 도착한 이 응답만으로 `/auth/me` 조회 누계가 4건에서 6건으로 늘고 지출 제어 화면 데이터가 재조회됐다. 재전송은 없었다. 현재 만료 처리 여부와 로그아웃 상태만 확인하므로 새 계정 조회 상태가 이미 정상으로 돌아오면 이전 변경의 에러 콜백도 새 세션에서 CSRF·보호 캐시 초기화 및 재조회가 가능하다. 새로운 mutation 401 처리의 경계 결함이다.

요청의 세션 세대를 캐시 및 전역 에러 처리까지 전달해 오래된 결과를 무시한다. 같은 세션에서 여러 401을 받을 때 처리 1회, 새 세션 뒤 이전 401의 캐시·토큰·안내 영향 0건을 한 테스트에서 확인한다.

### RVX-03 · HIGH · 원장 재조회 실패가 같은 탭의 조정 멱등 키를 제거

근거 ADR-026·066, [ReservationDetailPage.tsx:24](../../frontend/src/pages/ReservationDetailPage.tsx#L24), [ReservationDetailPage.tsx:129](../../frontend/src/pages/ReservationDetailPage.tsx#L129), [States.tsx:78](../../frontend/src/ui/States.tsx#L78).

Edge Mock API에서 SETTLED 조정 POST가 502를, 이어진 원장 재조회가 503을 반환하도록 했다. 최초 POST는 한 건이었으며 재조회 3회 실패 뒤 확인 창 0개, ‘기록 여부도 확인하지 못했습니다’ 안내 0개였다. 페이지의 ‘다시 시도’로 조회를 복구하고 같은 탭에서 같은 값을 입력하니 두 번째 POST의 멱등 키가 바뀌었다. 이는 브라우저 새로고침이나 탭 전환 없이 발생한다.

보조 확인이 화면과 동일한 상세 쿼리 키를 실패 상태로 바꾼다. QueryView가 폼과 모달을 제거해 메모리 키를 함께 잃는다. 이미 서버가 기록했으나 확인에 실패한 경우 다른 키의 재입력이 별도 조정이 될 수 있다. 보조 조회 실패를 상세 화면의 쿼리 상태와 분리하고 불확실 안내·확정 요청 본문·기존 키를 보존한다. 네트워크 또는 5xx 뒤 GET 실패에서 창·경고 유지, 자동 POST 0건, 수동 재시도 동일 키를 검증한다. 이 결함은 P-T02-05의 기존 새로고침·다른 탭 위험과 별개다.

## 추가 안전성 및 검증

- **A01 부분 해소.** 키가 원장에 있으면 기록 확인, 없으면 ‘아직’이라는 표현과 같은 키 안내, 자동 재전송 0건을 기존·신규 단위 테스트가 확인했다. 기록이 조회되지 않았다는 표시만으로 실패를 단정하지 않는다. 조회 자체가 실패하는 분기의 회귀는 RVX-03이다.
- **P-T02-05 조건부 수용.** 새로고침·다른 탭의 수동 재입력 위험은 이번 종료 보류의 독립 근거가 아니다. 그 위험은 실제 비용 및 유료 API 활성화 전에 해결해야 한다. 승인된 T03 설계 단계에서 서버 중심의 영속 요청 식별과 결과 조회·작업 복구를 검토한다. 내용이 같다는 이유만으로 키를 고정하는 방식은 정상 반복 조정의 의미를 보존할 수 없으므로 채택 범위에서 제외한다. T03 코드 작업은 이번 범위 밖이다.
- **A02 해소.** 소수 정밀도를 유지한 비교로 정확히 100% ‘한도 소진’, 초과 ‘한도 초과’, 0원 ‘전면 차단’을 구분한다. 단위 테스트에서 소수 6자리 경계 및 80% 임계값을 확인했다.
