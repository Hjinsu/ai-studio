## 3. 사전 점검 불일치와 결정

1. **Nano Banana 2 Lite 출력 한도 충돌**: 모델 문서는 Output token limit **4,096**, API `models.get`은 **65,536**. API 값 기준 최대는 호출당 약 3,641원(3회 10,923원)으로 상한 초과. 문서 값 기준은 228원. 근거가 충돌하므로 **사용자 결정으로 3회 보류**. 이미지 비교는 FLUX 단독 결과로 대체했다. Nano 비교가 필요하면 Google 측 확인 또는 1회 측정 호출(최대 3,641원) 별도 승인이 필요하다.
2. **fal 키 형식 오류**: 최초 `FAL_KEY`가 fal 형식이 아니어서 401. 사용자가 재설정. 유료 호출 전 단계라 비용 영향 없음.
3. **S2 실행 순서**: 계획은 CFULL → C1~C4였으나, CFULL(단일 화자 다중 part별 style)은 문서 예시가 없는 형태라 실패 시 남은 호출이 중단되는 위험을 줄이려고 **C1~C4를 먼저, CFULL을 마지막**에 실행했다. 비교 결과에는 영향이 없다.

운영 예시(산정): TTS 1회 약 21원 + FLUX 6장 36원 + Wan I2V 5s 4개 1,852원 = **약 1,909원**. 2027 TTS 단가 2배여도 약 1,930원이다. 사전 예약 기준은 TTS 상한을 60초 분량 1,500토큰으로 두면 약 27원(입력 1,500토큰 포함, 2027년 53원)이다.

## 9. Codex 인계 사항

S0 보고서 10절 C01~C12에 이어진다. 공통 설계·계약·migration·공통 문서는 Codex 담당이며, 반영하려면 사용자 승인이 필요하다.

| ID | 내용 | 제안 |
|---|---|---|
| H01 | TTS 호출 계약 | Gemini TTS는 `v1beta/interactions` 형식이다(`generateContent` 아님). `speech_config`는 배열 `[{voice}]`, style은 `annotations[{type: speech_metadata, style}]`, `store: false`. 응답 오디오는 `steps[].content[]`의 `type: audio`, `data`(base64), `mime_type: audio/wav`. 사용량은 `usage.total_input_tokens`, `total_output_tokens`, `output_tokens_by_modality`. `store: false`이면 응답 `id`가 없다. 요청 추적은 자체 callId로 한다 |
| H02 | TTS 예약 기준(C04 갱신) | `max_output_tokens`를 항상 지정하고 예약 = 입력 상한 + `max_output_tokens` × 출력 단가로 한다. 근거: CAPTEST 1회 관측(잘림·청구 ≤ 상한, `status: incomplete`). 공식 보장 문구가 없다는 점을 ADR에 명시한다. `status: incomplete`는 대본이 잘린 것이므로 실패로 처리하고 자동 재생성하지 않는다. 산정: 오디오 25토큰/초 |
| H03 | 전체 1회 합성 | C04의 TTS 호출 최소화를 채택한다. 장면 경계는 대본 part 순서와 무음 검출로 타이밍을 맞춘다. 장면별 합성이 필요하면 음량 정규화(예: -16 LUFS, TP -1.5 dBTP)를 필수 단계로 둔다 |
| H04 | Nano Banana 2 Lite | 문서(4,096)와 API(65,536) 출력 한도가 충돌한다. 해소 전에는 운영 공급자에서 제외하거나, 어댑터 시작 시 `models.get` 값으로 예약한다(1장 약 3,641원 → 사실상 사용 불가) |
| H05 | fal 키·가격 검증(C11 구체화) | 키 형식 `key_id:key_secret`을 시작 시 검증한다. pricing API의 `unit` 문자열은 `megapixels`, `seconds`다. 어댑터는 `endpoint_id`별 `unit_price`·`unit`·`currency`를 승인 가격표와 대조하고 다르면 발송을 거부한다 |
| H06 | fal 큐 처리 | 제출 응답의 `status_url`·`response_url`만 사용한다(경로를 직접 조합하면 405). 완료 시 `metrics.inference_time`을 기록한다. 타임아웃이 나면 같은 request_id로 조회만 하고 재제출하지 않는다 |
| H07 | Wan 기본값 차단(C08 확인) | I2V는 시작 이미지 비율을 따르므로 `aspect_ratio`가 없다. T2V에는 `generate_audio`가 없고 오디오가 붙어 나온다. 렌더에서 원본 오디오 트랙을 제거하거나 무시하도록 규칙을 둔다 |
| H08 | 최종 규격(C10) | Wan 출력은 720×1280 CFR 30fps다. 최종 1080×1920은 업스케일만 필요하고 프레임 변환은 필요 없다 |
| H09 | 공통 문서 갱신 | TASKS 제안: `V2-05-SPIKE | Claude Code | S2~S4 IMPLEMENTED(14/17 호출, Nano 3 HOLD), 사용자 청취·재생 평가 대기`. STATE·DECISIONS·V2-05_PROVIDER_SPIKE를 이 보고서 기준으로 갱신한다(통합 담당 Codex) |

## 10. 미검증·남은 일

1. **사용자 청취 평가**(S2 8개)와 **동영상 재생 평가**(S4 3개). Claude의 평가는 프레임 표본과 측정값 기준이다.
2. **콘솔 청구액 대조**: Gemini와 fal의 실제 청구액, 무음 할인 적용 여부, pricing API 조회의 과금 여부.
3. Nano Banana 2 Lite 비교(H04 해소 후 별도 승인).
4. 남은 실험 여유: 승인 호출 3회(Nano 보류분), 산정 기준 잔여 약 3,063원. 재생성은 건별 승인이 필요하다.
5. 2026 TTS 단가 승인은 KST 2026-12-30 19:00 전에 끝나는 호출에만 유효하다.

## 11. 검증과 비밀정보

- 원장 가드와 요청 본문은 `DRY=1` 오프라인 실행으로 검증한 뒤 유료 호출을 시작했다. 호출 14건은 모두 1회 발송·성공했다. 원장 집계 결과는 호출 14, 누적 1,937원이다.
- 출력 파일 23개의 해시는 작업 폴더 `SHA256SUMS-S2-S4.txt`에 있다.
- 비밀정보 검사: 작업 폴더의 요청·응답·원장에서 키 패턴, API 키 헤더, 서명 URL을 grep한 결과 0건이다. 저장소 변경은 이 보고서 하나이고 키, 생성 미디어, 결제 증빙은 없다.
- 다른 PC에서 재개할 때: 작업 폴더를 통째로 복사하고 `SHA256SUMS-S2-S4.txt`로 대조한다. 실행은 `node tools/run-tts.mjs <callId>`, `node tools/run-fal.mjs <callId> [시작 이미지]`다(원장에 있는 callId는 거부된다).
