# AI Studio v2 — 에이전트 착수 및 인수인계 (V2-00 검토 당시 지시)

현재 재개 절차는 [확정 NEXT_SESSION](../NEXT_SESSION.md)을 따른다.

이 문서는 사용자 승인 요청용이며 그 자체로 커밋, DB 접근, 유료 호출 또는 게시 권한을 부여하지 않는다. 기존 진행 중 작업을 먼저 보존한다.

## Codex에게 전달할 지시 (기존 T03-D 세션)

개발 방향을 AI Studio v2로 재설계한다. docs/v2/ 아래 01_PRODUCT.md, 02_TECHNICAL.md, 03_ROADMAP.md, 04_AGENT_HANDOFF.md를 읽는다. 기존 T03-C/D 구현을 그대로 완성하는 것이 목적이 아니다. 제품 기능 중심으로 필요한 코드만 선택한다.

V2-00만 우선 수행한다. 실제 repo의 main/integration/C/D 원격 SHA, 로컬 변경, 공통 계약, migration 파일 및 적용 여부를 확인 가능한 범위에서 조사한다. 사용자 DB에 접근하지 말고 미확인은 기록한다. T01/T02/T03-B 완료 기준을 새 브랜치 기준 후보로 삼아 재사용 목록과 의존성을 확인한다. C/D는 기존 WIP를 보존하고 재사용 여부를 파일/모듈 수준으로 분류한다. 원장, 멱등성 및 복구 안전 계약을 단순화할 경우 동등성 조건을 제시한다. 특히 자동 소재 발굴 전의 비용 귀속과 실행 식별자, 실제 검색 근거, 사용자 미입력부터 MP4까지의 흐름을 확인한다.

기존 AGENTS.md/CLAUDE.md/TASKS.md/STATE.md/DECISIONS.md/협업 가이드의 효력 및 충돌 정리안을 작성한다. 변경된 규칙은 승인 전 기존 규칙을 덮어쓰지 않는다. 새 v2 기준 브랜치 및 docs/v2 문서 반영 계획, V2-01 작업 분담, NEXT_SESSION.md를 제안한다. 기존 파일 삭제·강제 push·병합·제품 구현·Migration 변경·실제 지출·게시 금지. 현재 미커밋 문서는 안전 보존하고 회사 PC에서 가져올 방법을 제안한다. 별도 사용자 승인 후 지정 브랜치에서만 commit/push.

보고는 기준 SHA, 보존 상태, 재사용/제외 목록, 위험, 첫 구현 경로, 변경안, 다음 작업으로 제한한다. 전체 설계를 재작성하는 것이 아니라 새 기획과 실제 코드를 연결한다.

## Claude에게 전달할 지시 (기존 T03-C 세션)

AI Studio v2 재기획으로 기존 T03-C 추가 구현을 중단한다. 현재 브랜치와 원격 WIP, 미커밋 변경, 테스트 결과, V7 및 공통 계약 상태를 보존하고 보고한다. 기존 브랜치에서 v2 개발을 시작하거나 D 작업 폴더를 수정하지 않는다. Codex의 V2-00 결과와 사용자 승인 이후 새 v2 전용 작업 폴더에서 제품 구현을 시작한다. 승인 없이 커밋/푸시·병합·사용자 DB 변경·유료 호출·게시를 하지 않는다. 향후 제품 구현의 필수 목표는 채널 설정만으로 소재 자동 발굴부터 실제 Shorts MP4까지 실행되는 것이다.

## 새 브랜치 운영 (제안)
- 기존 main, t03/integration, t03/c-queue, t03/d-budget 보존.
- v2 기준 후보: 원격 t03/integration의 완료된 B 포함 SHA (실제 검증 필요).
- v2/integration: 승인된 기준 SHA에서 시작, 승인된 v2 문서 포함.
- v2/product: Claude 전용 worktree, v2/safety: Codex 전용 worktree. 필요할 때만 분리. 같은 파일 동시 수정 금지.
- Codex는 공유 Migration/OpenAPI/포트 담당, Claude는 제품 기능 담당. Codex가 작성한 비용 코드는 별도 Codex 세션에서 핵심 독립 리뷰.
- 작업 범위 승인 이후 자체 테스트와 구현은 연속 수행. 지정 브랜치 commit/push 일괄 승인은 사용자 선택. main 및 integration 병합은 사용자 승인.

## 회사 PC 재개
프로젝트 경로 예시 C:\Users\PC-94\Desktop\ai-studio. git fetch origin, git status --short, git worktree list, git branch -a를 확인한 뒤 승인된 v2 기준 및 문서 브랜치를 가져온다. 기존 작업 트리를 덮어쓰지 않는다. 실제 branch 생성/checkout/worktree 명령은 V2-00에서 검증한 원격 SHA와 충돌 상태를 반영한다.

마지막 보고의 C 원격 e7ef738, D 원격 3a976e1, 계약 6cd0c4e, 통합 dab7013은 축약값이며 원격 재확인 필요. 새 MVP 검토 문서가 이전 PC에만 있다는 보고가 있었으므로 새 v2 문서와 함께 보존 여부 확인. 사용자 DB/파일 백업은 필요할 때 별도 승인 후 수행. .env, 비밀번호, API 키, DB 덤프 및 산출물은 Git에 넣지 않는다. 실제 비용/게시 승인 상태는 장비별로 재확인한다.
