## 통합 예상 범위

- Spring Boot의 요청/단계 소유권, lease·fencing, SELECT와 선정 지문 및 기존 검증기를 재사용한다. Claude와 Codex는 DB에 직접 접근하지 않는다. 요청별 실행 방식을 고정하고 외부 파일 작업은 DISCOVER 및 선정 이후 RESEARCH/SCRIPT/SCENES에 연결한다.
- 최소 변경은 영속 작업 의도와 시도·due 상태, 파일 스키마 및 해시 검증, Windows 전용 런처·프로세스 격리, 결과 수집·채택, 요청 상세의 WAIT/보류 사유다. DB 스키마 변경 필요성은 기존 레코드 재사용 검토 뒤 승인 대상으로 둔다. 독립 큐나 자동 전환은 도입하지 않는다.
- Gemini LLM API는 사용자 선택 대안으로 남기고, 구독 모드가 불가하거나 대기 중이어도 자동 전환하지 않는다. 기존 미디어 순서, 예산 원장, 파일 무결성과 기술 QC, 사용자 인수 계약은 통합 후에도 유지한다.

## 통합 판정

W01~W07의 결과와 미검증 항목, 로그·파일 SHA-256, 인증/과금 경로, 대기 포함 처리량을 별도 보고한다. 공식 조건이 불명확하거나 API·추가 크레딧 전환을 차단할 수 없거나 stale/중복 채택 및 SELECT 우회가 발생하면 무인 통합을 보류한다. 통합은 격리 환경에서 기존 API·미디어 경로 회귀 및 독립 리뷰를 마치고 사용자의 최종 설계·구현/활성화 승인을 받은 후 진행한다. 상태는 PROPOSED다.
