## 0. 목표 및 범위

| 역할 | 우선 비교 후보 | 선정 기준 |

| 동영상 | Runway Gen-4 Turbo, Pika, Wan, Veo, Kling 후보 | 실제 움직임, 9:16, 비용, 복구 가능성 |
| 한국어 TTS | ElevenLabs, Google Chirp 3 HD 후보 | 자연스러운 억양, 전문용어, 정렬, 비용 |

모델명은 후보일 뿐이며 현재 API 판매·가격·상업 이용 조건을 보장하지 않는다. 계약 확정 전에 공식 가격 URL, 확인 UTC, SKU, 통화, 최소 청구 단위, 지원 길이/해상도, 실패/취소 과금, 세금, 멱등 키/조회 지원, 다운로드 만료, 라이선스/지역 제한, API 키 요건을 기록한다. 중개 공급자 가격과 원 공급자 가격을 섞지 않는다.

비교 표본: 동일한 시작 이미지와 동작 의도를 사용한 천체 회전/낙하 물체/코믹한 상황 3종, 한국어 TTS는 숫자·단위·영문 약자·능청스러운 문장 표본. 품질(움직임, 구도, 시간 연속성, 왜곡, 한국어 발음), 실제 청구액, 시간, 실패 및 재시작 복구 증거를 저장한다. 실제 호출 없는 계약 테스트와 공급자 문서 검증을 먼저 한다. 실험 예산은 별도 승인 대기(이전 제안 30,000원은 승인된 금액 아님). 필수 후보별 최소 비교만 실행하고 최종 공급자는 역할별 1개부터 시작한다. 자동 공급자 대체는 불확실한 과금이 해소된 경우에만 허용한다.

## D03. 한국어 소재·대본·장면 계약

기존 DISCOVER / RESEARCH / SCRIPT / SCENES 구조를 유지한다. 채널 config의 언어, 모델, voice, 스타일, 프롬프트 버전을 요청에 동결한다. 이미지/영상 프롬프트는 공급자별 영어 등 사용 가능하나 내레이션·제목·설명·자막은 한국어가 기본이다.

- DISCOVER: 중복 소재 배제, 첫 1~3초에 설명 가능한 호기심, 시각적으로 표현 가능한 사건 우선.
- RESEARCH: 출처 URL·확인 날짜·근거와 claim ID 보존. 가정 조건 및 실제 과학적 사실을 분리하고 추정은 표시. 확인되지 않은 수치나 출처 생성 금지.
- SCRIPT: 사건 중심 도입→상황 악화/전개→과학 설명→재치 있는 결말. 강제 농담 수 없음. 불필요한 인트로·반복·오해 유발 과장 금지. 참고 채널의 캐릭터·대사·음성 복제 금지. 상황 및 시각적 개그 우선.
- SCENES: segment ID 순서와 전체 coverage를 보존한다. AI는 장면 수·길이, 목적, 서사 중요도, 필요한 피사체 움직임, 시각적 개그·반전, 카메라와 SFX를 제안한다. 장면별 미디어 유형과 공급자·모델 후보, 비용 절감 대안을 함께 제안한다. 후보별 예상 비용은 백엔드가 승인 가격표로 산출해 비교 계획에 붙인다. AI 입력 가격·예산은 실행 근거로 사용하지 않는다.
- 한국어 대본 길이는 언어별 추정치로 발송 전 점검한다. 납품 길이 40~60초는 TTS 실측과 최종 출력으로 확정한다. IMAGE → TTS 순서에서는 실측 불일치 후 추가 발송을 막고 수정안을 검토한다. 확정된 대본은 덮어쓰지 않고 새 revision/승인된 기존 재생성 계약을 사용한다.

## D04. 미디어 연출 계획 및 예산 선택

기존 SCENES 결과에 장면별 우선 후보와 대체 연출을 담는다. 서버는 SCENES 완료 후 첫 미디어 발송 전에 순서·segment coverage, 예상 전체 길이, 핵심 사건·과학 사실·개그의 보존, 피사체 운동 요구, 모델의 길이·해상도·권리, 부모 자산 의존성 및 최악 청구액을 검증한다. 장면별 길이와 공급자 청구 길이는 별도다. IMAGE → TTS 순서를 유지하며 TTS 실측 후 확정 자산의 로컬 trim/pad로만 자동 조정한다. 기술 QC에서 최종 40~60초를 확인한다.

설명 컷에는 이미지나 도식을, 핵심 사건·시각 개그·반전에는 움직임을 전달할 수 있는 AI 클립 또는 검증된 절차적 애니메이션을 비교한다. 현상은 과학 근거의 재현성을 우선한다. 구도 연속성이 중요하면 I2V, 시작 이미지가 불필요하면 T2V를 검토한다. 정지 이미지의 확대와 카메라 이동은 피사체 운동으로 평가하지 않는다. 최초 인수는 이야기상 필요한 실제 움직임과 장면 효과를 검수한다.

품질 검증을 통과한 우선 계획이 예산 내면 채택한다. 초과 시 서사 중요도가 낮고 저렴한 대안으로 효과를 유지할 수 있는 장면부터 후보를 바꾸고 전체 검증을 반복한다. 이미 발송된 효과와 확정 자산은 고정하고 미발송 작업만 재구성한다. 동일 품질 후보는 최대 청구액이 작은 쪽을 우선하며 잔액 자체는 지출 근거가 되지 않는다. 유효한 완성 계획이 없으면 호출 전에 보류하고 사용자에게 비용 부족, 적합한 대안 없음, 가격 확인 불가 등 원인을 표시한다. 비교는 유한한 장면 후보 목록과 일관된 우선순위로 처리한다.

장면 계획 JSON 개념 예시(실제 API 스키마 아님):

```json
{
  "schemaVersion": 1,
  "sceneId": "s01",
  "segmentIds": ["seg01"],
  "mediaType": "IMAGE_TO_VIDEO",
  "imagePrompt": "cinematic planet, portrait composition",
  "videoPrompt": "planet visibly rotates around its axis",
  "subjectMotion": "ROTATION",
  "cameraMotion": "STATIC",
  "sceneAction": "행성 자전 표현",
  "requestedDurationMs": 5000,
  "purpose": "SCIENCE_REVEAL",
  "visualBeat": "자전으로 드러나는 의외의 장면",
  "providerModelCandidates": [],
  "fallbackMediaTypes": ["PROCEDURAL_ANIMATION"],
  "priority": "HIGH",
  "motionRequired": true,
  "startFrameAssetId": null,
  "endFrameAssetId": null,
  "presetId": null
}
```

서버 확정 계획에는 provider/model/SKU, 허용 길이·해상도·비용 최대액, 부모 asset/hash, 입력 hash, generation, 가격표 ID 및 대체 정책을 추가한다. 참조 ID는 같은 요청/run/소유권의 확정 자산에서만 선택. 선택적 end frame은 공급자 capability가 있을 때만 사용한다.

절차적 애니메이션 초기 후보: 천체 회전, 궤도, 방향 화살표/수치 비교. 고정 템플릿과 검증된 수치만 사용하며 임의 코드/셸/FFmpeg 필터 생성·실행 금지. 복잡한 범용 물리 엔진은 보류한다. 과학적 수치의 의미와 단위는 RESEARCH 근거와 대조한다.

## D05. 편당 3,000원 비용 보호

새 IFNOVA 실제 요청에는 활성 한도와 3,000원 중 낮은 값을 적용하고 기존 일·월 한도도 함께 검사한다. 공급자별 배분과 미디어 수량·비율·장면 길이에 따른 지출 목표는 두지 않는다.

- 계획 검증은 이미 인식한 비용 + 아직 인식하지 않은 활성 예약/미확정 과금의 최대 노출액 + 미예약 잔여 계획의 최대 청구액을 비교한다. 같은 operation의 인식액·잔여 예약·미확정액은 기존 원장 의미에 따라 중복 합산하지 않는다. 불명 비용의 상한을 확인할 수 없으면 보류한다.
- 실행 직전 기존 비용 엔진이 거래별 예약과 permit으로 최신 원장·한도·lease/epoch를 다시 검증한다. 계획 비교로는 발송 권한이 생기지 않는다. 예산이 바뀌어 잔여 계획이 들어오지 않으면 다음 예약·발송 전에 재구성하거나 보류한다.
- 외화 가격은 decimal 또는 정수 최소 단위로 처리하고 고정 환율 스냅샷·세금/수수료·반올림 규칙을 남긴다. 청구 가능 최대액을 보수적으로 원화 올림. 환율/가격을 확인할 수 없거나 최대 청구액을 보장할 수 없는 SKU는 자동 발송 차단.
- 공급자별 청구 분량(최소 클립 길이, 해상도, 토큰, 문자, 요청 단위)을 기준으로 계산. 실제 사용 영상 초와 청구 초를 구분한다. 예산 부족 시 미발송 계획의 품질/비용 조정만 허용. 미해결 operation이 있으면 기존 차단 유지.
- 실패·취소로 과금된 비용도 누적, 실제 과금이 예상 최대액보다 크면 증거를 숨기거나 임의 절삭하지 않고 정산·사고 기록 후 추가 발송 차단. 공급자 측 과금 통제/외화 변동 때문에 절대적 실청구 상한은 별도 검증이 필요하다.
- 공급자 계정 구독료 및 서버비는 별도 운영비로 표시하고 사용자에게 총원가도 보고한다. 공유 API 계정의 다른 프로젝트 사용량은 AI Studio 요청 비용과 구분한다.
- 재생성은 기존 결과·영수증 보존, 새 generation과 신규 승인된 효과 키, 잔여 예산 확인. 자동 재시도는 확실한 미발송 또는 공급자가 동일 요청 재개를 보장하는 경로만 허용.

## D06. 실제 공급자 어댑터 및 비동기 복구

기존 `ProductionCostService`, media item/asset 및 비용 포트의 예약·허가·증거·정산·적용을 확장한다. 공급자별 구현은 공통 typed 입력/결과만 반환한다. LLM, 이미지, TTS는 기존 호출 계약 우선; 비동기 영상은 submit/poll/download/reconcile/cancel capability를 명시한다. V13 및 비용 서비스가 MEDIA 효과를 IMAGE/TTS로 제한하므로 영상 준비는 IMAGE의 별도 하위 item으로 제안한다. 임의 12번째 단계를 추가하지 않는다.

| 논리 상태 (기존 enum과 매핑 예정) | 처리 |
|---|---|
| RESERVED / 미발송 | 동일 operation 재사용, 만료/취소는 미발송 영수증으로 닫음 |
| DISPATCH 허가 | current lease/epoch·비용·입력 hash 검증, 네트워크 호출 전 내구성 기록 |
| 제출 결과 확인 | 외부 job ID, 공급자 요청 ID, 제출 증거 영속화; 없는 경우 UNKNOWN |
| 실행 대기 | job ID로 조회, bounded backoff/timeout, Retry-After, 재시작 후 이어받기 |
| 완료 | 제한된 다운로드 → 원본 검사 → staging/해시 → 채택 → 증거/정산/적용 |
| 실패/취소 | 실제 비용 근거 기록, 과금 불확실 시 기존 복구 전용 상태 유지 |
| UNKNOWN | 조회·운영자 reconcile만 허용, 자동 신규 발송/대체/세대 증가 금지 |

위 표는 새 enum 확정안이 아니다. provider_operation 및 기존 상태 기계를 우선 재사용한다. job ID 저장 전 네트워크 단절은 공급자 멱등 키나 조회로 기존 작업을 확인할 수 있을 때만 복구한다. 확인할 수 없는 모델은 자동 재발송 금지 및 운영자 확인 필요. 단순 HTTP 성공/실패 코드만으로 과금 유무를 단정하지 않는다.

긴 폴링은 DB 트랜잭션 밖에서 진행하며 기존 lease 갱신/worker 점유 정책을 따른다. 대기 중 worker 반환이 필요하면 기존 플래너의 durable wake-up과 복구 전용 claim을 검토한다. 동일 효과에서 중복 submit은 금지하고 읽기 조회는 제한적으로 재시도한다. 취소 요청 이후 결과가 도착해도 비용 증거는 보존하되 현재 lease·취소 계약에 따라 공개/채택을 막는다.

비밀키는 환경/승인된 비밀 저장소에서만 읽는다. DB·로그·manifest에 원문 키, 인증 헤더, 서명 URL 저장 금지. 다운로드는 공급자별 승인 HTTPS 호스트, 리다이렉트/사설 IP 차단, 제한된 바이트·시간·파일 포맷. 사용자/LLM 제공 URL을 임의로 가져오지 않는다. 공급자 요청/응답 증거는 민감 정보 제거 후 보존한다.

## D07. 데이터 모델 및 파일 계약

기존 V13 `production_media_item`, `production_media_asset`, `provider_operation`, V12 `production_stage_result`와 요청·run·revision 연결을 재사용한다. 아래 항목의 저장 위치와 V14 최소 변경은 저장소 대조 문서의 D07 제안으로 구체화했다. 적용된 migration은 유지한다.

| 영역 | 필요 데이터 |
|---|---|
| 요청 프로필 | 콘텐츠 locale, voice, provider/model version, budget snapshot, output profile |
| 장면 계획 | scene/segment IDs, media type, duration, motion intent, priority, immutable canonical input/hash |
| 공급자 작업 | operation ID, provider job ID, submit evidence, 조회 상태/시각, 가격 스냅샷, 비용 증거 |
| 가격표 | provider/SKU, currency, billing unit/minimum, 최대 비용, 확인 날짜, 출처, 환율 snapshot |
| 미디어 자산 | 원본/정규화 클립 역할, 부모 ID/hash, MIME, byte/hash, probe 결과, 권리, epoch |
| 콘텐츠 검수 | revision/manifest hash, QC 버전, 사실 검증 결과, 사용자 판정/시각/사유 |

동일 정보가 기존 JSON/레코드에 있으면 중복 테이블 생성 금지. 외부 job ID의 유일 범위는 실제 공급자 계정/namespace를 고려한다. 외부 응답을 직접 신뢰하지 말고 현재 요청/operation 소유권을 검사한다. FK·unique·불변 필드를 기존 트리거/계약과 일치시킨다.

Workspace에 원본 파일 및 파생 파일을 별도 역할로 저장하고 SHA-256과 lineage 보존. 파일 확정 및 비용 증거의 분리된 내구성 경계, stale worker fencing, 원자 이동, 참조 없는 scratch 자동 정리 계약 유지. B01/B02 수정된 복구 동작을 실제 공급자에도 회귀 검증한다. 바이너리 DB 저장, 임의 경로 및 정적 디렉터리 노출 금지.

## D08. 한국어 음성·자막·타임라인

초기 장면 단위 TTS 유지 후보. 전체 낭독/문장 단위는 비교 결과로 선택한다. voice ID, 언어, 발음 사전 버전, 원문 해시, 공급자 정렬 정보를 저장한다. 발음 보정은 원문 자막과 별도 필드로 관리하고 의미가 달라지지 않도록 확인한다. 숫자·SI 단위·영문 약자는 테스트 대상.

기존 PCM 48kHz 샘플 기준 타임라인, 프레임 반올림, 마지막 음성까지 보존 정책 유지. 자동 잘라내기, 과도한 속도 변경, 임의 침묵 삽입 금지. 길이 불일치 시 QC 보류 또는 승인된 수정/재생성. 자막은 공급자 타임스탬프 또는 검증된 정렬을 사용하고 추정만으로 싱크 PASS를 부여하지 않는다. 한국어 조사/어절/문장부호, 실제 글리프 bbox, 2줄 및 기존 safe-area를 검사한다. 원문 coverage 및 ASS 이스케이프 유지.

출력 프로필 후보: `BURNED`(한국어 ASS 번인), `CLEAN`(번인 없음 + 한국어 SRT). 기본 인수 프로필은 사용자와 스파이크에서 선택한다. 항상 두 MP4를 만들 필요는 없다. 출력 variant는 manifest 및 QC와 구분해 동일 원본 계보를 유지. 글로벌 게시용 번역 가능 SRT 제공, 번인 자막은 자동 번역되지 않는다는 점을 UI에 표시한다.

## D09. 혼합 렌더링 및 자원 안전성

동영상 원본은 제한된 크기/길이/해상도/코덱 및 실제 전체 디코딩을 검사한다. V2-04의 검증된 FFmpeg/ffprobe 실행기, Windows Job Object, Linux cgroup v2 fail-closed, 3GiB 메모리, 전용 scratch 최대 32GiB, 최소 여유 5GiB, 초기 1GiB 예약 및 기본 동시 렌더 1개 유지. 실제 동영상 입력의 scratch 예상 사용량을 측정해 예약을 늘릴 필요가 있으면 기존 정책을 완화하지 않고 별도 계약 승인을 받는다.

1. 클립 원본 해시/권리/probe 검증. 영상 공급자의 포함 오디오는 기본 제거; 명시적 권리 및 연출 승인이 없으면 사용 금지.
2. 기존 규격으로 CFR/해상도/색공간 정규화. 저해상도 확대는 기존 QC 제한과 일치. 9:16 아닌 입력은 안전한 fit+pad 또는 승인된 crop. 주요 피사체 잘림 차단.
3. 장면 duration과 클립 길이를 대조. 긴 클립은 중요 동작을 보존하는 검증된 trim 범위만 사용, 짧은 클립은 장면 재구성/허용된 정지 구간 또는 승인된 재생성. 임의 루프나 프레임 반복을 실제 운동 분량으로 계산하지 않는다.
4. IMAGE/CLIP/PROCEDURAL 입력을 동일 ordered timeline으로 합성하고 기존 cut/fade, PUNCH_IN, ASS, BGM ducking/SFX, loudness 정규화 유지. 최종 -18..-14 LUFS, true peak ≤ -1 dBTP 등 기존 승인 기준 적용.
5. 고정 argv/필터 템플릿, 경로 containment 및 ASCII scratch 별칭 사용. AI가 생성한 임의 명령·식·파일 경로·네트워크 입력 금지.
6. 확정 자산만 재사용하며 렌더 재시도가 신규 유료 요청을 유발하지 않도록 한다. 디스크 압박, 취소, stale lease, JVM 종료 후 보호·정리 정책 유지.

## D10. 기술 QC 및 콘텐츠 QC

기존 32개 기술 QC의 의미를 보존하고 신규 동영상 관련 검사를 버전 관리한다. 클립 무결성, actual motion coverage(실제 영상/절차적/카메라만 구분), 프레임/PTS, duration 및 장면 coverage, 소스 오디오 제거, 출력 variant 및 자막 싱크, 권리 기록, 예산 증거를 검사한다. 기술적 움직임 검출은 참고 지표일 뿐 카메라 이동과 피사체 운동을 완벽하게 판별한다고 가정하지 않는다.

콘텐츠 QC는 기술 PASS와 별도다. 사실 claim/출처 일치, 가정 명확성, 첫 3초 흡입력, 사건 중심 흐름, 실제 움직임, 반복/왜곡, 자연스러운 한국어 발음, 농담 및 결말, 자막/음악/SFX를 확인한다. AI 검수 결과는 권고·검토 근거이며 인간의 인수를 대체하지 않는다. 실제 영상에 표시된 사실도 확인한다. 자동 QC 실패, 권리 불명, 비용 불명은 공개/게시 승인 차단. 기술 미리보기 권한과 향후 게시 가능 상태는 구분한다.

사용자 승인 대상은 특정 manifest/MP4 hash와 revision에 묶는다. 자산이나 출력 변경 시 새 검수가 필요하다. 기존 QC 마지막 시도 APPLIED 복구(B02)와 동일한 경계를 새 출력에도 유지한다. 본 단계에선 YouTube 게시하지 않는다.

## D11. API 및 UI 변경 제안

기존 `ProductionRequestController`, 요청 상세, 미디어 조회·Range 및 인증을 우선 확장한다. 아래는 논리 API이며 실제 경로는 기존 OpenAPI에서 확인 후 확정한다.

| 요청 생성/계획 확인 | 예상 비용·최대 비용, 영상 분량 및 미디어 유형, 준비 실패 사유 |

## D12. V2-06 이관

격리 MariaDB만 사용. 실제 외부 호출 없이 장애 주입/모의 공급자로 대부분 검증한다. 실제 공급자 스파이크와 인수 호출만 별도 승인·비용 기록. 최종 CI, Gitleaks, diff check, OpenAPI/생성 타입, 전체 단위/통합/프런트 테스트 및 실제 보호 렌더 증거 보존. 실제 Linux 배포 렌더 미검증 상태이면 실행 차단 유지. 사용자 DB·main·기존 migration 변경 금지.

### 최초 실제 영상 인수 체크

- 한국어 대본·낭독·자막·제목/설명, 40~60초, 1080×1920 CFR30.
- 실제 피사체가 움직이는 핵심 컷이 있으며 단순 슬라이드 반복이 아님.
- 과학적 가정 및 근거, 상황 코미디와 이야기 흐름을 사용자 확인.
- 내레이션·자막·BGM·SFX 균형 및 영상 전환 확인.
- 실제 가격/영수증/실패 및 재생성 비용 포함 3,000원 상한 평가, 불명 정산 없음.
- 권리 및 공급자 약관 근거, MP4/SRT/QC/manifest 및 SHA-256 보존.
- 실제 게시 0건. 독립 리뷰 승인과 사용자 최종 병합 승인 전 DONE 금지.
