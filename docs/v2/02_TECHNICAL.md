# AI Studio v2 — 최소 기술 설계

상태: V2-00 기준 승인. 세부 스키마는 V2-01에서 확정한다. 기존 안전 계약의 핵심 결과를 유지하며 TX1~TX7·FD·C-G·CD-G의 구현 구조는 참고한다. 동등한 안전성을 검증할 수 있는 더 단순한 구조를 우선한다.

## 구조
Java/Spring Boot/MyBatis/MariaDB/Flyway + React + 로컬 FFmpeg/FFprobe. 기존 버전·빌드·인증 유지. 단일 JVM, loopback 기본, worker 1개로 시작(기존 상한 2 유지), DB 영속 상태. PC가 종료되면 실행 중단, 재시작 시 복구. 외부 호출은 DB 트랜잭션 밖에서 수행. 비밀은 환경변수 또는 보호된 로컬 설정, 로그/manifest/Git에 저장 금지.

## 재사용 및 분기
기준 후보는 완료된 T01/T02 및 T03-B가 포함된 origin/t03/integration (마지막 보고 dab7013). main과 실제 원격 전체 SHA, 테스트, Migration 체크섬 확인 후 새 v2 개발 브랜치 생성. C e7ef738, D 3a976e1, 공통 계약 6cd0c4e는 보고된 축약 SHA이며 현행 원격 확인 필요. 기존 C/D와 main/integration 보존, 강제 push/삭제 금지. T03-C/D는 일단 동결, 검증된 부분만 재사용. 기존 Flyway V1~V6 파일 변경 금지; V7 C WIP 및 V8 D 초안은 적용/배포 여부 확인 후 선택. 이미 적용된 migration 수정 금지. 기존 사용자 DB는 읽기/쓰기 모두 사전 승인, 새 격리 DB에서 구현 검증.

## 최소 데이터 모델 (논리 모델, DDL 아님)
| 개념 | 목적 |
|---|---|
| channel, topic, content, content_revision, content_run | 기존 엔티티 재사용, 채널 설정/후보/실행 입력 스냅샷 |
| job, attempt | 단계·장면별 실행 상태, 횟수, 소유권, 오류, 재개 |
| provider_operation | 논리 작업 키, 요청 해시, 예약 ID, dispatch 여부, 외부 ID, 결과/비용 상태 |
| budget_* / cost_log | 기존 비용 원장 재사용, 예약·확정·해제, 일/월/채널/콘텐츠 한도 |
| asset / manifest | 상대 경로, SHA-256, 유형, 생성 설정, 출처/권리, 입력 해시 |
| approval / publish_intent | 승인된 revision/run/manifest/hash, 업로드 의도·원격 ID·결과 |

기존 테이블/포트가 같은 역할이면 신규 중복 테이블을 만들지 않는다. 스키마/API의 구체적 변경은 기능 작업에 맞춰 한 번씩 결정한다. 소재 발굴 전에도 실행 식별자와 비용 상한이 있어야 한다. 기존 콘텐츠가 소재를 선행 요구한다면 별도 영속 제작 요청 또는 비용 보호된 소재 작업을 제안하고, 선정 후 기존 topic/content/run에 연결한다. 소재 발굴 비용도 동일한 제작 요청 예산에 귀속하며 한도 우회/이중 계산 금지.

## 실행 흐름
DISCOVER → SELECT → RESEARCH → SCRIPT → SCENES → IMAGE/TTS → SUBTITLE → RENDER → METADATA → QC → REVIEW_READY. 고정 단계와 장면 리스트만 사용, 범용 DAG 엔진 불필요. 이미지와 TTS는 의존성이 없을 때만 병렬. 초기에는 직렬 실행도 허용. 로컬 렌더링 입력 및 산출물 해시를 저장한다. 기존 상태 머신 재사용 여부는 검토 결과에 따르며 아래는 사용자 관점의 상태다: 대기 / 실행 / 재시도 대기 / 검수 대기 / 복구 필요 / 완료 / 실패 / 취소. 비용 미확정 작업은 종료 처리하지 않는다. 실행 소유권과 fencing, 원자적 상태/로그 업데이트, 중복 Run 차단 유지. 재시도는 최대 3회(최초 포함 제안), 명시적 수동 재개 제한 및 오류 분류 적용. 불명 유료 효과는 자동 재시도 금지.

## 유료 호출 안전성 (삭제 불가 조건)
1. 논리 효과마다 영속 operation key(실행/단계/장면/입력 버전)와 요청 해시를 만든다. 동일 키 다른 요청은 거부.
2. 외부 호출 전 가격/통화/최대 비용 검증, 기존 원장으로 원자 예약. 한도를 알 수 없으면 호출 금지. 일/월/채널/콘텐츠 한도와 kill switch를 적용.
3. 실제 호출 허가를 DB에 영속 기록하고 성공적으로 기록한 소유자만 호출. 트랜잭션 안에서 네트워크 호출 금지. 허가 후 종료/타임아웃/응답 유실은 불명 처리. 제공자가 보장하는 멱등·조회 계약이 검증되지 않았다면 다시 보내지 않는다.
4. 외부 ID와 응답 증거를 보존하고 예약 확정/해제 및 영수증을 중복 없이 처리. 큐 적용 전 장애 시 영수증 재적용만 수행. 과거 정책·동결·정산 계약과 잠금 순서를 단순화하려면 동등한 안전성을 검증하고 별도 승인한다.
5. 재시작 시 실행 중 상태를 점검. 호출 전 확정된 실패와 로컬 무효과 작업은 재시도 가능, 불명 유료 결과는 조회/수동 정산. 예약 해제는 미실행 증거 필요. 취소는 추가 호출을 막되 이미 발생한 비용을 지우지 않는다.
6. 기존 T02 원장과 C/D 계약의 핵심 결함(중복 실행, 잠금 역전, 고아 run, 정산 누락)을 재도입하지 않는다. 두 worker 경합, 장애 주입, 중복 요청을 격리 DB에서 검증한다. 사용자는 한 명이지만 중복 효과 위험은 남는다.

## 파일 및 부분 재생성
로컬 workspace/{channel}/{content}/{run}/ 하위에 inputs, research, script, scenes, assets, audio, subtitles, render, manifest. 경로는 서버가 생성하고 traversal 차단, 임시 파일 작성 후 원자 이동, 해시 검증. DB에는 상대 경로와 생성 이력. 입력/템플릿/모델 버전이 바뀌면 영향받는 단계만 새 효과 키로 재생성하며 기존 승인 무효화. 기존 파일은 참조가 남아 있는 한 보존. DB와 파일을 함께 백업한다.

## 게시 안전성
최종 MP4·metadata·manifest를 검수해 revision/run/manifest/hash에 승인 연결. 실제 파일 해시 재검증 후 업로드 의도 영속화, 비공개 기본, OAuth 최소 권한. 업로드 불명 시 원격 조회 및 복구, 맹목적 재업로드 금지. 공개는 별도 승인. 변경된 산출물은 재승인. FAKE 파일은 게시 금지.

## 검증 기준
기능 단위 자체 테스트 + 핵심 위험 독립 리뷰. 기존 회귀, 두 커넥션 예산/실행 경합, 호출 전후 종료, receipt 재전달, 파일 손상, 부분 재생성, 취소, 재시작, 승인 변경, 업로드 불명 검증. 기존 DB migration 권한/binlog 관련 검증 유지. 100k 부하, 다중 서버 검증은 제외. 실제 API/YouTube 검증은 사용자 승인과 한도 설정 뒤 실행.

실제 공급자와 외부 자료의 사용 조건 및 기존 비용 보호 재사용은 [공급자·원가 제안](06_AI_PROVIDER_AND_PRICING.md)과 [소재 발굴·데이터 API 제안](07_TOPIC_DISCOVERY_AND_API.md)을 참조한다.
