# V2-02 소재 자동 발굴 및 선정 최소 구현 설계

기준 `origin/v2/integration` `91c3e9ad1394b1c9b122231a60b8acc5a8d873b8` · 승인 후 공통 계약 착수 · 신규 테이블 **1개**. 첫 대상은 IFNOVA 영어 과학 Shorts다. 채널 선택과 제작 시작으로 후보를 발굴하고, 기본 자동 모드에서는 소재 입력 없이 선정한다. [로드맵](03_ROADMAP.md)과 [품질·수익화 요구사항](05_CONTENT_QUALITY_AND_MONETIZATION.md)을 따른다.

## 기존 코드 재사용 범위

- `production_request`가 발굴 전 제작 요청 ID, 채널 설정 revision, KRW 한도를 고정한다. 기존 11단계 순서, 단일 실행 lease와 fencing, 취소, 비용 확인 후 종료 규칙을 유지한다. 기존 단계의 `result_ref`는 512자 참조이며 큰 후보 본문은 별도 저장한다.
- DISCOVER는 `ProductionCostPort`의 예약·단일 발송·정산·영수증 경로로만 생성 효과를 실행한다. SELECT는 `ProductionSelectionPort.link`를 사용해 같은 트랜잭션에서 Topic·Content·초기 Revision·FAKE Run을 연결하고 실행기가 Run 시작과 SELECT 완료를 기록한다.
- `TopicNormalizer`의 정규화와 채널별 해시 조회, `TopicService`·`ContentService`의 연결 규칙, 기존 Topic·최근 및 관련 Content의 현재 revision을 재사용한다. 후속 조사·대본·렌더 단계는 기존 FAKE 경로를 사용한다. V2-02 인수 범위는 후보 발굴부터 선정 연결까지다.

## 소재 후보 데이터 구조

**`production_discovery` 1개**를 제안한다. 요청당 1행이며 PK는 `production_request_id` FK다. 후보는 최대 10개 고정 묶음이다. 검색 대상은 기존 채널 카탈로그이고 화면은 요청별 묶음을 조회하므로 후보별 테이블이나 벡터 인덱스 없이 처리할 수 있다. 기존 `provider_operation`에는 비용 증거와 영수증만 두고 후보 본문은 이 행에 저장한다.

| 저장 항목 | 내용 |
|---|---|
| 시작 스냅샷 | 모드 `AUTO / MANUAL`, 후보 수 5~10(기본 8), 요청 생성 당시의 채널 언어, 프롬프트·평가 규칙의 공통 버전. 채널 설정 ID는 항상 요청 행에서 조회한다. 변경 가능한 채널 언어를 DISCOVER 또는 SELECT 시 다시 가져오지 않는다. |
| 생성 결과 | 공급자 작업 ID(고유 FK), 정규 JSON과 SHA-256, 생성 시각. 서버가 원 응답 순서로 안정된 후보 ID를 부여한다. 후보별 핵심 주제·질문, 영어 제목, 차별화 관점, 40~60초 구성안, 근거 확보 계획, 사실 주장 및 근거 참조를 저장한다. |
| 평가 결과 | 후보별 기준별 점수·총점, 차단 코드, 비교한 Topic/Content 및 revision ID, 유사성 근거와 차별화 사유. 평가 버전과 시각, 최초 평가와 SELECT 시 재검사 결과를 구분한다. |
| 선택 결과 | 묶음 버전, 수동 선택 의도(후보 ID·선택자·시각), 최종 선정 후보·모드·근거·시각. 최종 선택은 생성 본문 해시와 후보 ID에 연결한다. |

요청 생성 시 시작 스냅샷을 함께 커밋한다. 기존 요청에 스냅샷이 없으면 묵시적으로 현재 설정을 복제하거나 새로운 비용 효과를 등록하지 않고 기존 V2-01 실행 계약을 적용한다. JSON은 길이와 항목 수를 제한하고 생성 결과는 한번 기록한 뒤 덮어쓰지 않는다. 원시 오류 응답, 인증값 및 공급자 내부 메시지를 저장하거나 화면에 노출하지 않는다.

## 생성 프롬프트 및 응답 계약

- 공급자 인터페이스는 `DiscoveryProvider.generate(ProductionDiscovery.Input) → ProductionDiscovery.Response`로 제한한다. 호출 주체는 발송 허가를 커밋한 비용 어댑터다. 실행기는 스냅샷 기반 정규 입력으로 가격이 붙은 요청을 제시하며 직접 공급자 호출을 하지 않는다. **R05** FAKE는 요청 ID와 정규 입력을 함께 시드로 사용한다. 동일 요청의 재실행은 같은 후보와 해시를 반환하고 서로 다른 요청은 여러 과학 소재와 관점을 다르게 조합한다.
- 고정 프롬프트에는 영어 과학 Shorts 대상·시청자·채널 전략·금지 소재, 스냅샷의 Shorts 길이 범위, 지정 후보 수를 전달한다. 하나의 핵심 질문을 짧게 설명하는 제목, 다른 설명 관점, 도식·비교 등 장면 전개, 확인 가능한 출처 유형과 검색 질문을 요구한다. 채널 설정 문자열은 데이터로 취급한다. 미확인 주장을 사실로 표현하거나 출처를 지어내지 않도록 지시한다.
- 응답은 버전과 `candidates[]`를 가진 JSON 객체다. 각 후보는 `coreTopic`, `centralQuestion`, `title`, `angle`, `outline[]`(2~5개), `evidencePlan[]`(출처 유형·검색 질문), `assertions[]`(주장·근거 ID, 없으면 빈 배열), `suggestedScores`와 평가 근거를 반환한다. URL 제안이나 공급자의 자체 검증 표시는 검증 근거가 되지 않는다.
- 서버는 UTF-8 본문 최대 32KiB, 지정 수와 응답 버전, 정확한 필드·유형·필수값, 공백·제어문자·정규화 후 빈값, 중첩 깊이, 항목 수와 길이를 검사한다. 제목은 기존 Topic 제한인 255자 이내다. 점수는 정수이며 기준별 범위를 검사한다. 합산과 최종 채택 여부는 서버가 계산한다. 잘못된 응답을 성공으로 기록하지 않는다.
- 요청 해시는 정규 입력·프롬프트 버전·가격을 묶으며, 재시도와 재시작은 기존 효과 키를 재제시한다. **R06** 비용 어댑터는 검증된 정규 응답 본문·해시를 증거 접수 트랜잭션에 함께 보존하고, 영수증에는 내부 결과 참조(`discovery:{requestId}`)와 본문 해시를 남긴다. 평가와 연결 전에 요청·공급자 작업·본문 해시의 일치를 확인한다. 저장된 본문으로 평가와 영수증 적용을 재생한다. 발송·실제 비용이 확인된 형식 오류는 비용을 확정하고 실패 처리한다. 결과 불명은 예약을 보존한 복구 상태로 둔다.

## 중복 검사와 평가 규칙

아래 R01~R07은 현재 결합 검증의 기준이다. [정책 개정](05_CONTENT_QUALITY_AND_MONETIZATION.md#4-소재와-대본-독창성)에 따른 후속 변경은 아래 별도 항목에 기록한다.

1. 같은 채널의 Topic 전체에서 정규화 해시를 조회한다. 후보 묶음 안의 동일 제목과 동일 질문도 비교한다. 최근 100개 및 관련 키워드가 겹치는 최대 100개의 Content를 합쳐 제목·핵심 질문·초기 또는 현재 revision brief와 설명 관점을 비교한다. 보관 콘텐츠도 중복 근거에 포함한다. 과거 brief에 질문이 분리되어 있지 않으면 기존 제목과 brief를 비교 근거로 사용한다.
2. **R02** 입력을 정규화한 뒤 영문 핵심어 집합과 2단어 구문을 버전화한 규칙으로 비교한다. 첫 규칙은 같은 핵심 질문에 대해 핵심어 Jaccard 0.80 이상이며 설명 관점이 겹치면 차단하고, 0.60 이상에서 관점이 불명확하면 경계 후보로 보류한다. 질문·관점의 근거가 뚜렷하지 않은 단순 표현 변경은 어휘 점수가 낮아도 차단한다. 정확한 제목 해시 일치나 실질적으로 같은 질문·설명 관점의 표현 변경은 차단한다. 같은 분야라도 질문과 관점에 유의미한 차이가 있고 근거가 설명되면 통과할 수 있다. 판단하기 어려운 경계 후보는 자동·수동 모두 차단하고 비교 대상과 사유를 남긴다. 초기 규칙의 키워드 기반 비교는 동의어, 은유, 다른 표현으로 같은 질문·관점을 설명한 후보를 놓치고 공통 어휘가 많은 별개 질문을 잘못 차단할 수 있다. 동일 의미 표현 변경과 유사 어휘의 별개 질문을 fixture로 검증하고, 실제 AI 연동 단계에서 승인받은 의미 기반 평가로 보강한다.
3. 심각한 중복(`DUPLICATE`), 채널 금지 소재(`CHANNEL_PROHIBITED`), 검증 근거가 없는 사실 주장(`UNSUPPORTED_ASSERTION`)은 점수와 별도로 차단한다. 금지 소재는 고정 채널 설정의 `providerOptions.discovery`에 있는 구조화된 금지 주제·용어 및 버전 규칙으로 확인한다. 구성안과 제목에도 단정 표현 검사를 적용한다. V2-02는 서버가 미리 승인한 근거 ID만 신뢰하며, 그런 근거가 없으면 질문과 조사 계획만 채택할 수 있다. 실제 출처 조사는 V2-03에서 수행한다.
4. 통과 후보의 점수는 흥미도 0~25, 채널 적합성 0~20, 독창성 0~20, 시각화 가능성 0~15, 근거 확보 가능성 0~15, 비용 효율성 0~5다. 평가자는 각각 질문의 매력, 채널 전략·길이 일치, 비교 결과와 차별화, 장면으로 설명 가능한 구조, 조사 계획의 구체성, 빠른 도식화·재사용 가능성을 버전화한 규칙으로 채점한다. **R01** 근거 수준을 0%·25%·50%·75%·100%로 구분한다. 근거 없음·단서만 있음·부분 충족·대부분 충족·완전 충족 순서다. 항목별 최대점에 비율을 곱해 내림한 정수를 더한다. 총점은 100점이다. 모델 점수는 참고 근거로 사용한다. 합계가 같으면 근거 확보 점수, 독창성 점수, 안정된 후보 순으로 결정한다.

## 자동 및 수동 선정 흐름

1. DISCOVER는 설정 스냅샷 확인, 비용 보호를 통한 FAKE 호출, 응답 검증 및 후보 평가를 수행한다. 평가 저장, 영수증 적용, DISCOVER 완료를 요청의 동일 fenced 트랜잭션에서 커밋한다. 통과 후보가 한 명도 없으면 근거를 보존하고 발굴 단계를 실패 처리한다. **R03** 이번 범위에서 추가 유료 발굴과 자동 재생성을 수행하지 않는다.
2. **R04** AUTO는 SELECT에서 최고 순위의 적격 후보를 선택한다. MANUAL은 DISCOVER 완료 후 SELECT를 `PENDING`으로 두고 lease를 반납한다. 공개 요청 상태는 기존 `RUNNING`을 유지하고 조회 API의 `awaitingSelection`으로 대기를 표시한다. 저장된 단계·묶음으로 재시작 뒤에도 대기를 재구성한다. claim은 DISCOVER 성공·SELECT 대기·수동 의도 없음의 조합을 제외하고, 선택이나 취소가 커밋되면 다시 처리한다. 이미 발생한 효과의 복구는 이 조건보다 우선한다. 사용자는 통과 후보를 선택하거나 취소할 수 있다.
3. 수동 선택 명령은 요청 소유권·묶음 버전·유효 후보·취소 상태를 요청 락 아래 검증하고 의도만 기록한다. 동일 선택 재전달은 기존 결과를 반환한다. 다른 후보 재전달과 오래된 묶음 버전은 충돌로 처리한다. 수동 선택의 변경은 SELECT 실행 전 재검사로 후보가 무효화되어 다시 대기할 때만 가능하다.
4. **R07** SELECT는 요청 락 → 채널 행 배타 락 순서로 최신 카탈로그를 대조하고, 같은 트랜잭션에서 연결과 선택 근거를 커밋한다. Topic 등록·Content revision 수정이 채널 공유 락을 사용하는 기존 경로와 직렬화한다. 선택에서 예산 락이나 공급자 호출을 획득하지 않는다. 자동 모드에서 후보가 탈락하면 다음 적격 후보를 검토한다. 수동 후보가 탈락하면 이유를 저장하고 남은 후보가 있는 경우 다시 대기한다. 통과 후보가 소진되면 실패한다. 이 재검사는 SELECT 시도 차감 전에 수행한다.
5. 최종 연결 지문은 요청 ID, 후보 ID, 생성 본문 해시, 최종 선택 근거 버전, 제목·brief·길이를 정규화해 계산한다. `ProductionSelectionPort`에는 배열이나 후보 본문 대신 선정 제목과 brief, 스냅샷에 맞는 길이를 전달한다. 영어 스냅샷을 Revision에 적용하도록 포트의 선택 값에 언어를 추가하고, 기존 호출의 채널 언어 해석 경로도 지원한다.

| 영역 | 현재 결합 기준 | 후속 최소 변경 |
|---|---|---|
| 유사성 | `SIMILARITY_UNCERTAIN`은 차단 코드다. 차단 코드가 하나라도 있으면 자동·수동 후보 모두 부적격이다. | 동일 질문·동일 관점 및 제목·표현만 바뀐 소재는 차단한다. 독립 가치가 확인된 일부 유사 소재는 독창성 점수를 감점하고, 같은 분야의 새 질문과 관점은 허용한다. 불확실 후보는 검수 필요로 분류하고 자동 선정에서 제외한다. UI에서 차단·감점·검수 필요 상태와 각각의 근거를 구분한다. |
| 사실성 | 근거 없는 사실 주장과 단정 표현은 `UNSUPPORTED_ASSERTION`으로 차단된다. | 과학적 질문, 가설, 가상 시나리오와 전제, 미검증 주장을 구분한다. 미검증 주장은 조사 대상으로 구조화해 RESEARCH에 전달하고 SCRIPT에서 실제 출처와 주장별 근거를 확인한다. 허위 출처, 확인된 오류와 검증 전 단정의 차단을 유지한다. |
| 후보 소진 | 적격 후보가 없으면 실패하고 추가 발굴하지 않는다. | 모든 소재가 부적합할 때 동일 요청의 남은 예산 내에서 최대 한 번 재발굴하는 방안을 별도 검토한다. 불명 효과의 재발송이나 비용 복구 우회를 허용하지 않는다. |

V2-02의 최소 수정 범위는 표의 유사성 행이다. 기존 평가 JSON, 비교 근거, 묶음 버전을 우선 사용하고 초기 평가와 SELECT 재검사의 자동 선정 조건을 일치시킨다. 아래 결합 검증과 함께 차단·감점·검수 필요 표시, 실질 중복 및 수동 선택 안전 경로의 회귀를 확인한다. 재발굴, 신규 테이블·정책 엔진, 비용 엔진·실행 안전성·기존 Migration 변경은 범위 밖이다. 주장 인계는 V2-03, 최종 품질 점수와 부분 개선은 V2-05에서 구현한다.

## DB/API/UI 변경 범위

- DB는 V10 후보 묶음 테이블 1개와 FK·제약·인덱스를 추가한다. V9 요청을 backfill하지 않는다. V1~V9 및 기존 상태 CHECK는 유지한다. 신규 테이블의 읽기·삽입·갱신만 기존 운영 DB 계정 권한에 추가한다.
- 기존 `POST /api/v1/production-requests`에 선택적 `selectionMode`와 `candidateCount`를 받는다. 신규 SHORTS에 `v2-discovery-1`을 부여한다. LONGFORM은 기존 실행 경로를 사용하고 비기본 소재 옵션은 400으로 거절한다. 공통 단계에서 기존 실행기는 `v2-fixed-1`만 claim하며 신규 요청은 제품 결합까지 대기한다. 기본값을 적용한 요청 본문을 멱등 비교에 사용하고, 기존 키·본문 해시가 저장된 요청의 재생도 유지한다. `GET /api/v1/production-requests/{id}/discovery`로 후보·평가·선택 상태를 조회하고, `POST /api/v1/production-requests/{id}/selection`에 후보 ID·묶음 버전을 보내 선택 의도를 기록한다. 기존 소유권·인증·CSRF·오류 코드를 사용한다.
- 관리자 콘솔의 제작 시작/상세 화면에 자동·수동 모드, 후보 카드 또는 표, 기준별 점수·차단 사유·비교 대상·선정 근거, 수동 선택·취소를 표시한다. 저장된 결과를 조회하고 대기 중 다시 불러올 수 있게 한다. `ui/`, `layout/` 및 디자인 토큰을 사용한다. 로딩·빈 상태·오류·권한·세션 만료, 라이트·다크·모바일을 처리한다. 지출이 가능한 제작 시작은 확인 대화상자를 거치고 금액은 문자열로 표시한다.

## 핵심 인수 테스트

- 기존 요청 재생 및 미지정 자동 기본값, 설정 또는 채널 언어 변경 후 기존 요청 스냅샷 유지, IFNOVA 영어 Shorts의 정상 후보 수·필수 정보·저장 근거·자동 연결 검증.

- 비용 스위치·요청 한도·기존 일일/월간/채널 한도 적용, 동시 dispatch 1회, 불명 시 예약 보존, 저장 후 장애에서 후보·영수증 재생, 형식 오류 시 실제 비용 보존. 후보가 전부 차단된 경우 후속 단계·추가 발굴 금지.

- 두 요청의 동일 후보 선택 경합에서 실질 중복 신규 콘텐츠 방지. Topic·Content·Revision·Run 연결 및 단계 갱신 예외 시 전체 롤백, 동일 지문 재실행 시 기존 연결 반환.
- API 계약·타입 생성, 화면에서 후보·근거·선정 확인과 수동 동선, 오류·권한·세션 만료, 라이트·다크·모바일. V2-01 회귀는 실제 비용·선정 포트와 격리 DB에서 실행하고 공급자는 FAKE를 사용한다.

## Claude 착수 지시

- `v2/02-product` worktree에서 `v2/02-common`과 기준 SHA가 동일한지 확인한다. Claude는 생성·평가·선정 로직, 실행기·UI와 자체 테스트를 소유한다. `discovery/persistence`와 공통 계약 변경은 Codex에게 전달한다.
- `ProductionDiscovery`, `DiscoveryProvider`, `DiscoveryEvaluator`를 기준으로 R01~R05를 구현한다. `DiscoveryExecutionPort`는 실행기와 안전 담당의 접점이다. 제품 브랜치 자체 테스트에서는 이 포트의 대역을 사용하고 실제 비용·영수증 및 카탈로그 구현은 안전 브랜치와 연결한다. 모델 응답 검증과 가짜 후보의 요청별 다양성은 순수 테스트로 검증한다.
- `ExecutionMapper.nextClaimable`의 공통 제한을 제품 통합 시 확장한다. 기존 파이프라인은 그대로 처리하고 신규 파이프라인만 새 DISCOVER/SELECT 경로를 사용한다. 수동 대기에서 lease 반납·재시작·취소·불명 효과 복구를 검증한다.
- 비용 담당과 R06 영수증/본문 재생과 R07 동시 선택 및 잠금 순서를 실제 두 포트로 결합 검증한다. 실제 공급자 연결과 최종 통합 병합은 별도 승인 범위다.
